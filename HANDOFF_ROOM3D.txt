EXISTING MANUAL WORKFLOW (START HERE)
Read tools/room3d_retouch.py, room3d_additions.py, room3d_editor.py and
room3d_catalog.py inside worktree29, plus docs/ROOM3D_FOUNDATION.md sections
"Non-destructive room retouching" and "Offline editor and integrity-checked catalog".
Retouch edits generated OBJ groups in separate output directories; never writes
over automatic exports. Supported edits: translate, positive scale, yaw, pivot,
hide, plus explicit procedural additions. Optional reprojection updates textures.
It saves retouch.json with source OBJ SHA256, edits, group bounds, additions and
appearance mode. retouch-appearance.json carries appearance semantics through
sequential edits. Existing tests cover actual rendering, source immutability,
sequential reprojection, additions and fixture material roles.
Browser editor exports edits for the CLI; it is a wireframe/object-transform
editor, not a complete arbitrary mesh-modeling application.
Current retouch persistence is export-based. No batch integration automatically
replays a versioned correction chain after regeneration. Source hash is recorded
but replay compatibility and stable identity must be designed/enforced.
Current primitive_N group names can shift when automatic inference changes;
blindly applying an old edit to the same index risks editing the wrong object.
Do not advertise current retouch.json as a complete portable override format:
it contains an absolute source path, and addition records need inspection for
whether they preserve full reproducible parameters.
